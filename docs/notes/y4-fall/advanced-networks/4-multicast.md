
# 4. 组播

[multicast](https://en.wikipedia.org/wiki/Multicast)

## IP组播

**IP组播**是指在IP网络中将数据包以尽力传送（best-effort）的形式发送到网络中的某个确定节点子集，这个子集称为一个组播组（multicast group）。

源主机只发送一份数据，该数据的目的地址为组播组地址，只有组播组内的主机才可以接受该数据

**优点**：

- 降低网络流量、负担

**缺点**：

- 传输不可靠（best effort 的缘故）
- 组播报文的复制开销，路由器的资源消耗增加
- 可控可管性差

    - 用户管理
    - 安全

### IP组播模型

兼容IP服务：使用**UDP**传输组播分组

开放的组：组播源无需知道组成员，只需要知道组地址；**源可以不是组成员**；一个组可以有任意数量的源节点

组播组具有动态性：可以随时加入或离开

### 组播地址

`1110` 开头的地址：`224.0.0.0` 到 `239.255.255.255`

其中私人组播地址空间：`239.0.0.0` 到 `239.255.255.255`

一些比较有名的组播地址：

- `224.0.0.0`　基础地址，保留，不能被任何群组使用
- `224.0.0.1`　全主机群组（all hosts group），指参加本IP组播的所有主机、路由器、网关（不是指整个互连网）
- `224.0.0.2`　本子网上的路由器（all routers on a LAN）
- `224.0.0.5`　本子网上的OSPF*路由器(all　OSPF　routers　on　a　LAN)
- `224.0.0.6`　本子网上被指定的OSPF路由器(all　designated　OSPF　routers　on　a　LAN)　 

## MAC组播

做法是将 IP 组地址的低 23 位代替 MAC 地址的低 23 位

e.g.

MAC 地址为 `01-00-5E-00-00-00`，组播地址为 `224.66.60.89`

首先将 IP 地址转换成二进制：`11100000.01000010.00111100.01011001`，取后面的 23 位：`1000010.00111100.01011001`，转为 16 进制为 `42-3C-59`，则映射完的地址为 `01-00-5E-42-3C-59`

缺点：可能会映射到同一个以太网地址上，虽然概率很小

> 至于为什么是 23 位，因为提出这个标准的人当年只买得起一个 24 位的标识符，去了其中 23 位做研究
