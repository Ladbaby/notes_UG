## 3.1 Kruskal's Method to Find a Minimum Spanning Tree
数据结构学过，过程如下:
- 一开始所有节点都被视为minimum spanning tree
- 每次找到不同tree之间的最小权重边，并添加到最终结果之中。注意==不能形成闭环==(想要判断新加的边是否会形成闭环也很简单，只要看新加的边的两个顶点是否都已经被包含在结果之中了，是的话就必定会形成环)
- 假如结果包含$n-1$个边了就结束(就是恰好包含所有节点了)

关于这个算法的时间复杂度:
- Sorting

    $O(m\log m)$来排列有m个边的图
- The union of two sets

    $O(m)$合并两个树的复杂度
- The finding of an element in a set

    $O(m)$因为要判断每次添加的边的对应节点是否已经存在于结果中了

所以整个算法的复杂度是$O(m\log m)$。鉴于最坏的情况下节点数为$n$时，$m=C^2_n\approx n^2$所以时间复杂度是$O(n^2\log n)$

## 3.2 Prim's Method to Find a Minimum Spanning Tree
显然又是学过的，找的是==已经存在的树==的下一个最近节点(也就是说已经在树里的任意一个节点都可以作为当前节点)

这个算法的方便之处就在于，它可以从任意一个结点出发

鉴于这个算法在每选择一个新结点的时候，都要遍历一遍所有节点，所以最坏情况和平均情况都是$O(n^2)$

所以，当边的数量$m$比较小的时候，*Kruskal's method*更好；当$m$的数量较大的时候（指m=$O(n^2)$），那么*Prim's algorithm*就更好

## 3.3 The Single-Source Shortest Path Problem
就是*Dijkstra's algorithm*

书上的过程确实说明了怎么个找局部最优解，大概意思是一开始令节点集合$S=\{v_0\}$，然后每次循环的时候，找到从$S$里面所包含的所有节点出发，走一步可能到达的下一个节点的最短路径（每一个可能的节点都要求出自己的最短路径），然而并不是所有的这么多最短路径都是被接纳的最终结果，我们只接纳这些最短路径之中==值最小的==那个最短路径及其对应的节点。

比如下一步可以去到:
$$
L(v_2)=\min(6,L(v_1)+c(v_1,v_2))=4\\
L(v_3)=\min...=5\\
...
$$
这么多最短路径里面$L(v_2)$最小，所以我们只接受$v_2$，并把$v_2$添加到集合$S$里面

至于时间复杂度，就是$O(n^2)$

## 3.4 The 2-Way Merge Problem
我们都知道*Merge sort*，那么在面对多个已经排好序的队列的时候，鉴于每次只能操作两个数列，我们应该如何选择合并的顺序呢?

答案是和*Huffman Coding Tree*一个道理的，先合并最小的俩序列

建立这么一个*Merge tree*所需要的时间是$O(n\log n)$
